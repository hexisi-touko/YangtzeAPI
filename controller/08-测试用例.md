# 测试用例

这些文件以 `_test.go` 结尾，通常不会参与生产程序运行，而是用来固定接口行为、权限边界和回归问题。先读对应的生产文件，再读测试会更容易。

## 按主题看

- 认证：`auth_flow_test.go`、`auth_session_test.go`、`passkey_test.go`、`telegram_test.go`、`misc_oidc_test.go`
- 渠道和模型：`channel_authz_test.go`、`channel_test_internal_test.go`、`channel_upstream_update_test.go`、`model_list_test.go`、`model_owned_by_test.go`
- 配置校验：`option_claude_test.go`、`option_gemini_test.go`、`theme_compat_test.go`
- 额度和 Token：`token_test.go`、`token_auto_groups_test.go`、`usedata_flow_test.go`
- 支付和订单：`payment_webhook_availability_test.go`、`return_path_test.go`、`topup_quota_limit_test.go`、`topup_waffo_pancake_test.go`
- 用户管理：`user_manage_test.go`

## 运行方式

在 `new-api` 目录执行：

```powershell
go test ./controller
```

测试失败时先看失败测试名和测试数据，再回到对应的 `.go` 文件。测试文件是学习业务规则的“可执行说明书”，但不能替代阅读路由和 service。
