# 系统任务与运维

这一组负责系统状态、后台任务、性能观察、审计和部署相关接口。它们更像“网关自身的运行管理”，不直接实现某个上游模型协议。

## 建议顺序

1. `misc.go`：状态、公告和关于信息，认识系统级接口。
2. `system_info.go`：运行实例和节点信息。
3. `performance.go`、`perf_metrics.go`：性能统计、缓存和指标。
4. `system_task.go`、`system_task_handlers.go`：定时任务的创建、调度和处理器。
5. `deployment.go`：部署/模型部署相关设置。
6. `audit.go`、`uptime_kuma.go`：审计记录和外部可用性监控。

## 文件地图

- `misc.go`：系统状态、通知和关于页面接口。
- `system_info.go`：实例登记、查看和清理。
- `performance.go`、`perf_metrics.go`：性能统计、缓存清理、指标汇总。
- `system_task.go`：系统任务的增删改查和当前任务。
- `system_task_handlers.go`：定时任务类型及具体处理器注册。
- `deployment.go`：模型部署设置和相关服务连接。
- `audit.go`：管理员操作审计信息。
- `uptime_kuma.go`：读取 Uptime Kuma 等监控数据。

这些接口常与 `common/`、`logger/`、`setting/` 及后台任务服务配合。部署时只开放必要的管理入口，并为管理员账号启用强认证。
