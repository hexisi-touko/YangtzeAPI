# Controller 学习导航

这里的 `.go` 文件都属于同一个 Go 包 `controller`。本目录的业务分组是给人看的导航，不是把源码移动到多个 Go 子包；因此不会改变路由、导入路径或编译结果。

## 先理解一条请求

```text
浏览器或客户端
  -> router：根据 URL 找入口
  -> middleware：登录、API Key、限流、审计
  -> controller：接收参数，调用业务层，返回响应
  -> service：执行业务规则
  -> model：读写数据库
  -> relay/channel：把统一请求转换成上游厂商协议
```

后台页面通常从 `router/api-router.go` 进入；模型中转通常从 `router/relay-router.go` 进入。

## 推荐阅读顺序

1. `setup.go`：第一次初始化管理员，先认识一个最小接口。
2. `user.go`、`auth_session.go`：登录、会话和用户身份。
3. `channel.go`、`model.go`：上游渠道和可用模型。
4. `token.go`、`billing.go`：成员如何拿到 API Token，以及用量如何计算。
5. `relay.go`：真正接收 `/v1` 请求并转发到上游。
6. `service/`、`model/`、`relay/channel/`：沿着 controller 调用继续向下追。
7. `08-测试用例.md`：用测试反过来确认每个功能的输入和预期结果。

## 看代码时问自己

- 这个函数对应哪个 URL？去 `router/` 搜索它的注册位置。
- 参数从哪里来？看 `gin.Context` 的路径参数、查询参数、JSON 或表单绑定。
- 规则在哪里判断？controller 只负责流程，复杂规则通常在 `service/`。
- 数据保存在哪里？沿着 `model/` 找数据库表和 GORM 操作。
- 出错如何返回？观察项目统一的响应和错误处理方式。
