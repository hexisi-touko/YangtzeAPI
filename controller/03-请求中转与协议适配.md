# 请求中转与协议适配

这一组是项目最核心的“网关”部分：客户端用统一的 `/v1` 接口请求，New API 选择渠道、转换格式、调用上游，再把结果返回给客户端。

## 建议顺序

1. `relay.go`：统一中转入口和响应处理。
2. `task.go`：异步任务的查询，理解非即时返回的请求。
3. `video_proxy.go`、`video_proxy_gemini.go`：视频结果代理和 Gemini 视频地址处理。
4. `midjourney.go`、`image.go`：图片/绘图类任务。
5. `playground.go`：后台试调用入口。

## 文件地图

- `relay.go`：接收 relay 请求、选择处理器、记录使用渠道和错误。
- `task.go`：查询用户任务和任务状态。
- `video_proxy.go`、`video_proxy_gemini.go`：视频数据代理及 Gemini 专用处理。
- `midjourney.go`：Midjourney 任务查询和状态更新。
- `image.go`：图片生成相关接口。
- `playground.go`：管理后台中的模型试用/调试入口。

## 一条中转调用链

```text
客户端 POST /v1/...
  -> router/relay-router.go
  -> middleware：API Key、限流、审计
  -> controller/relay.go
  -> service：选渠道、预扣/结算额度
  -> relay/channel/<provider>：协议适配
  -> 上游 API
  -> 返回结果并写入用量日志
```

`relay.go` 只看懂流程即可；具体 OpenAI、Claude、Gemini 等协议差异，继续看 `relay/channel/`。
