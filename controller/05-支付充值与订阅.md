# 支付、充值与订阅

这一组是可选的商业化能力。课题组自用时可以先了解接口边界，不必一开始就接入所有支付渠道。

## 建议顺序

1. `topup.go`：充值总入口和通用配置。
2. `redemption.go`：兑换码/兑换记录。
3. `subscription.go`：订阅套餐和余额支付。
4. `payment_compliance.go`、`payment_webhook_availability.go`：支付合规确认与 Webhook 可用性检查。
5. 各 `topup_*.go`、`subscription_payment_*.go`：具体支付供应商实现。

## 文件地图

- `topup.go`：充值信息、充值订单和通用支付辅助逻辑。
- `topup_creem.go`、`topup_stripe.go`、`topup_waffo.go`、`topup_waffo_pancake.go`：不同充值支付渠道。
- `subscription.go`：订阅套餐、订阅状态和余额支付。
- `subscription_payment_creem.go`、`subscription_payment_epay.go`、`subscription_payment_stripe.go`、`subscription_payment_waffo_pancake.go`：订阅支付渠道。
- `payment_compliance.go`：启用支付前的合规确认。
- `payment_webhook_availability.go`：检查支付回调配置是否完整。
- `redemption.go`：兑换码的生成、查询和兑换。
- `return_path.go`：支付完成后回到后台页面的路径处理。

支付回调需要结合 `router/`、`service/` 和供应商签名校验一起看。不要把支付密钥写进源码或提交到仓库。
