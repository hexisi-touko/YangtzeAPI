# 渠道与模型

这一组回答两个问题：New API 可以把请求发给哪些上游渠道，以及每个渠道提供哪些模型。渠道可以理解为一条上游 API 连接，模型是这条连接可提供的能力。

## 建议顺序

1. `channel.go`：渠道列表、新增、修改、启停和删除。
2. `channel-test.go`：从后台测试某个渠道能否正常调用。
3. `channel_authz.go`：哪些字段允许修改，哪些属于敏感变更。
4. `model.go`：对外展示和筛选模型。
5. `channel_upstream_update.go`、`model_sync.go`：从上游同步模型。
6. `channel-billing.go`、`channel_affinity_cache.go`：渠道余额、计费信息和亲和性缓存。
7. `model_meta.go`、`vendor_meta.go`、`option.go`：模型/厂商元数据和系统选项。

## 文件地图

- `channel.go`：渠道 CRUD、状态筛选和渠道配置。
- `channel-test.go`：渠道连通性与模型调用测试。
- `channel_authz.go`：渠道敏感字段保护。
- `channel_upstream_update.go`：合并、增加、删除上游模型名称。
- `channel-billing.go`：渠道鉴权头、余额查询和渠道计费辅助逻辑。
- `channel_affinity_cache.go`：渠道亲和性缓存的查看和清理。
- `model.go`：模型列表、分组和对外模型格式。
- `model_sync.go`、`missing_models.go`：模型同步和缺失模型检查。
- `model_meta.go`、`vendor_meta.go`：模型、厂商的元数据管理。
- `option.go`：系统选项及模型相关配置。

## 关联位置

后台渠道页面在 `web/src/features/`，路由注册在 `router/api-router.go`；真正向不同厂商发请求的适配器在 `relay/channel/`。先看 controller 如何接收配置，再追到适配器会更容易。
